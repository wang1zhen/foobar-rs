# 无障碍状态与验收清单

范围：桌面端键盘操作、焦点、AccessKit/读屏、高对比、高 DPI、中文 IME。
**状态说明**：本项目没有通过外部无障碍审计；下面是基于代码的现状和发布前必须人工走一遍的清单。
自动化测试只覆盖 headless 布局，不包含读屏或真实 IME。

## 键盘操作

默认快捷键（设置 → 快捷键里可改；组合键解析见 `fb-ui/src/shortcuts.rs`）：

| 操作 | 默认键 | 备注 |
| --- | --- | --- |
| 播放 / 暂停 | `Space` | 焦点在文本框内时不触发 |
| 下一首 / 上一首 | `Ctrl+Right` / `Ctrl+Left` | macOS 上 `Command` 等同 `Ctrl` |
| 聚焦搜索框 | `Ctrl+F` | 只聚焦，不选中已有文本 |
| 打开设置 | `Ctrl+,` | |
| 布局编辑 | `F2` | |
| 关闭对话框 | `Esc` | 设置、自动列表、标签编辑、电台等弹窗 |
| 远程搜索提交 | `Enter` | 焦点离开远程搜索框时提交 |
| 在控件间移动焦点 | `Tab` / `Shift+Tab` | egui 内建焦点链 |
| 调整滑杆 | `←` / `→` | 进度条与音量自绘并显式处理（±2%）；EQ 用 `egui::Slider` 的内建键盘支持 |

规则与边界：

- 文本框获得键盘输入时（`egui_wants_keyboard_input()`）或设置对话框打开时，全局快捷键整体让位，
  避免输入空格/字母时误触播放（`fb-ui/src/app.rs::handle_shortcuts`）。
- 快捷键匹配要求修饰键完全一致，`Ctrl+Shift+Right` 不会误触 `Ctrl+Right`。
- 文件/目录选择使用系统对话框（rfd），键盘行为由桌面环境决定。
- 托盘菜单、MPRIS/系统媒体键由平台提供，不在应用内键盘链里。

### 键盘缺口

- **自绘控件没有 Enter/Space 激活**：按钮、导航项、胶囊、曲目行、专辑卡、星级都用
  `Sense::click()` + `response.clicked()`。egui 的 `Sense::click()` 让控件可被 Tab 聚焦，
  但不会把回车/空格合成点击；因此 Tab 能看到焦点环，却仍要鼠标才能执行。这是“键盘全操作”的
  主要阻断项，需要给每个自绘控件补 `Key::Enter/Space` 处理（或改用 egui 的 `Button`）。
- **没有焦点陷阱**：对话框在 `ui()` 末尾绘制，Tab 仍可能走到遮罩后的控件；关闭后也没有把焦点
  还给打开它的控件。
- **列表/网格没有方向键导航**：曲目行、专辑卡只能 Tab 逐个走，没有上下/左右移动或 Home/End。
- **没有助记符/菜单加速键**：顶栏菜单依赖指针。
- **状态栏与错误信息**是绘制文本，没有作为 live region 主动播报（见读屏部分）。

## 焦点顺序

当前顺序跟随控件创建顺序，而不是视觉阅读顺序：

1. 顶栏（菜单、主题切换、搜索框）
2. 底部播放栏（因为 `Panel::bottom` 在导航/内容之前创建）
3. 左侧导航
4. 右侧检查器（如果该布局显示）
5. 主内容（工具栏、列表/网格）
6. 对话框（设置 / 自动列表 / 标签编辑 / 电台，最后创建）

焦点环由 `widgets::focus_ring` 绘制：2 px 主色描边 + 控件形状，不只靠颜色变化。
验收时确认：每个可点击控件 Tab 到时都有可见焦点环；焦点环在深/浅色下都清楚；`Esc` 关闭对话框后
焦点回到合理位置（当前未实现，需记录实际落点）。

## AccessKit / 读屏

- `fb-app` 的 eframe 启用了 `accesskit` 特性；egui 会为内建控件生成 AccessKit 节点。
- 自绘控件通过 `Response::widget_info` 提供名称/角色：按钮、播放键、专辑卡、播放列表行、
  电台行、评分星（“评分 N 星”）、滑杆（`Role::Slider`）。文本框用 `labelled_by` 关联可见标签。
- Linux 需要 at-spi2/DBus；Windows 走 UIA；macOS 走 NSAccessibility。
- **未用任何读屏实测**。选中状态用 `WidgetInfo::selected` 表达；主题/预设等选择在视觉上是胶囊或卡片，
  读屏可能读成“按钮（已选中）”而不是单选组，属于语义偏差。
- 曲目/专辑的可见文字是 painter 直接绘制；读屏依赖控件名称，逐列信息（时长、格式、评分）不一定
  能单独导航。状态栏文本没有节点/live region，操作结果（“扫描完成”“保存失败”）可能不播报。

### 读屏验收（NVDA / VoiceOver / Orca 各走一遍）

| 步骤 | NVDA（Windows） | VoiceOver（macOS） | Orca（Linux） |
| --- | --- | --- | --- |
| 启动后读标题/窗口 | UIA 树里有 “foobar-rs” | VO+U 窗口列表 | Orca 焦点/窗口标题 |
| Tab 依次经过顶栏、播放栏、导航、内容 | 播报名称与角色 | 每项有 label | 每项有 label |
| 聚焦搜索框输入中文 | 读输入内容与预编辑 | 读 composition | 读 composition |
| 执行播放/暂停（鼠标或快捷键） | 状态变化是否播报 | 同左 | 同左 |
| 曲目行/专辑卡 | 读出标题+副标题、选中状态 | 同左 | 同左 |
| 评分星 | “评分 N 星”可操作 | 同左 | 同左 |
| EQ/音量滑杆 | 读数值与单位 | 同左 | 同左 |
| 设置对话框 | 能进入、Tab 不跑出、Esc 关闭 | 同左 | 同左 |
| 错误路径（扫描失败/无音频设备） | 状态文本是否播报 | 同左 | 同左 |

任一项失败都记到本文件“已知缺口”，不要只留在 issue 里。

## 高对比

- 只有 Material 3 深/浅两套配色（`fb-ui/src/tokens.rs`），**没有高对比主题**，也不读取
  Windows 强制颜色 / macOS 增强对比 / GNOME 高对比设置（egui 自绘，系统主题不生效）。
- 选中/悬停/焦点分别用容器色、描边色和 2 px 焦点环；文字与背景的对比度尚未逐项计算。
  状态胶囊用文本 + 颜色双编码，但列表选中仍主要是颜色差异。
- 验收：在系统高对比/强制颜色下启动，确认没有出现“只有颜色能区分”的状态；用取色工具抽查
  正文、次要文字、禁用态、焦点环与背景的对比度（目标 ≥ 4.5:1，正文大字/图形 ≥ 3:1）；
  记录未达标项。

## 高 DPI

- 缩放因子来自 winit，egui 以 point 布局；没有手动覆盖或用户缩放选项。
- 行高、图标按钮（40–44 px）、焦点环宽度都按 point 定义，会随系统缩放放大。
- 已知风险：分数缩放（125%/150%）下 1 px 描边和自绘图标可能发虚；固定行高的虚拟化列表在
  极端缩放或字体回退时可能裁字；测试 rect 只在默认缩放下跑过。
- 验收矩阵：100%、125%、150%、200%、250%（含分数缩放），每个比例检查：文字不裁切、省略号
  正确、星级/图标可点、焦点环完整、窗口最小尺寸下播放栏不重叠、中文与拉丁混排基线一致。

## 中文 IME

- 文本框使用 egui `TextEdit`，IME 事件由 winit 转入；搜索、远程搜索、标签编辑、设置、电台 URL、
  自动列表查询都走同一路径。
- 输入法组合期间焦点在文本框内，全局快捷键被 `egui_wants_keyboard_input()` 拦下，空格不会触发
  播放；`Ctrl+F` 也不会在组合中抢焦点（需实测确认）。
- 尚未在真实输入法上验收：预编辑下划线、候选窗跟随光标、长拼音串、标点、中英切换、`Esc`
  取消组合（可能同时触发对话框关闭，需确认优先级）。
- 随包字体只覆盖简体中文与拉丁；日文假名、韩文、生僻字会回退到 egui 默认字体，组合输入可能看到
  缺字（见 `assets/fonts/README.md`）。

### IME 验收

1. 中文输入法（fcitx5/ibus 拼音、微软拼音、macOS 拼音各至少一个）在搜索框输入“周杰伦”，
   确认预编辑、候选、上屏、退格都正常，列表随上屏结果过滤。
2. 组合中按 `Space` / `Ctrl+F` / `F2`，确认不会触发播放、搜索聚焦或布局编辑。
3. 在标签编辑对话框输入中文并保存，重启后标签仍是原文；确认候选窗不遮挡输入框。
4. 125%/150% 缩放下重复 1–3，确认候选窗定位和焦点环不偏移。
5. 用 `Esc` 取消组合，确认不会误关整个对话框（若会，记为缺口）。

## 已知缺口汇总

| 缺口 | 影响 | 位置 |
| --- | --- | --- |
| 自绘控件无 Enter/Space 激活 | 键盘用户无法完成大部分操作 | `fb-ui/src/widgets.rs`（按钮/行/卡片/星级） |
| 对话框无焦点陷阱/焦点恢复 | Tab 可跑到遮罩后，关闭后焦点丢失 | `fb-ui/src/app.rs::ui` 末尾的对话框 |
| 列表无方向键导航 | 10k 曲目只能 Tab 遍历 | 名单/网格渲染 |
| 状态/错误无 live region | 读屏用户不知道操作结果 | 顶栏状态文本 |
| 无高对比主题/不响应系统对比设置 | 低视力用户体验差 | `tokens.rs` |
| 主题/预设等选择用“按钮 + selected”语义 | 读屏不把它当单选组播报 | `widgets::chip` / `preset_card` |
| 未做 NVDA/VoiceOver/Orca 实测 | 上述节点/播报问题未知 | — |
| 未做真实 IME 与高 DPI 实测 | 中文输入/缩放可能出问题 | — |
| 无 reduced-motion/动画开关 | 目前动画很少，影响低 | — |

修复优先级建议：自绘控件键盘激活 → 焦点陷阱/恢复 → 状态播报 → 高对比主题 → 列表导航 →
读屏语义（复选框/逐列信息）。
